# AIMAN — Master Blueprint

## 1. Mission
AIMAN is an owner-first AI operating system that converts natural-language goals into verified outcomes using reasoning, research, planning, memory, agents, tools, execution and quality control.

## 2. What makes AIMAN different
AIMAN is not a single chatbot. It is a coordinated system that can decide what must be learned, research missing knowledge, select tools, delegate work, execute, inspect results, recover from ordinary failures, and deliver a verified artifact.

## 3. Core architecture
```text
Owner -> Interface -> AIMAN Core
                    -> Brain / Planner
                    -> Model Router
                    -> Memory / RAG
                    -> Mission Engine
                    -> Agent Manager
                    -> Tool Engine
                    -> Execution Adapters
                    -> Verification / Recovery
                    -> Security / Approval / Audit
```

## 4. Main capability families
- Personal assistance and communication
- Research and intelligence
- Software engineering
- Design and content production
- Business operations
- Automation and integrations
- Computer/browser execution
- Analytics and reporting
- Proactive intelligence
- Controlled learning
- AI Civilization simulation

## 5. Zero-to-final contract
Given a document, goal, or problem, AIMAN should be able to understand requirements, research unknowns, create a plan, assign tasks, produce artifacts, test them, fix ordinary defects, verify acceptance criteria, and report exactly what was done.

## 6. Knowledge principle
If AIMAN does not know something, it should not pretend. It should identify the knowledge gap, use permitted research tools, collect evidence, assess source quality, and then update the mission context with sourced findings.

## 7. Autonomy principle
Autonomy is bounded by permissions and risk. Low-risk reversible work can be automated. Consequential external actions can require owner approval. Prohibited actions are blocked.

## 8. Memory principle
Memory is structured by scope. Current task context must not accidentally become permanent personal memory. Secrets are never stored as ordinary memory.

## 9. Verification principle
Every important outcome has explicit acceptance criteria. An agent saying “done” is not verification.

## 10. Evolution principle
AIMAN is modular and provider-agnostic. Agents, models, tools, databases and interfaces can be replaced without rewriting the entire system.

## 11. Production boundary
Self-improvement can generate proposals, tests and reports. Production code/configuration changes require a controlled deployment path.

## 12. Sandbox boundary
AI Civilization is a simulation. It has virtual resources and identities and no real-world financial, credential, legal or physical authority by default.
